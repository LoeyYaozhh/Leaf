## 二、关键实现说明

### 2.1 三个核心纯函数（§4.5 逐条对齐）

- **`deriveDueDates(plan, range)`**：`eachDayOfInterval` → 过滤 `startDate/endDate` 生效期 → `matchesFrequency`。`daily` 全命中；`specific_weekdays` / **`weekly_n` 用 `candidateWeekdays`**（`timesPerWeek` 只在 `PlanManager` 做 UI 校验提示，不参与推导）；`custom_dates` 取 `dates` 集合。返回升序去重 `ISODate[]`。**请假不进集合**（它是打卡状态）。`deriveAllDueDates` 复用本函数做成员级并集。
- **`computeStreak(dueDates, statusByDate, today)`**：只取 `d <= today`；`leave → continue`（不中断、不计入）；`done → running++` 并更新 `longest`；`pending`/缺失 → `running = 0`；`current` 从最近应完成日往前扫，遇 `pending` 即 `break`。休息日不在集合内天然不中断。`canBackfill(date, today)` = `0 ≤ differenceInCalendarDays(today, date) ≤ 7`。
- **`computeSpaceView(state, viewerId)`**：`self_only` **短路返回 `viewerId === ci.memberId`**，结论不被计划级 `hiddenInSpace` 改写（作者本人在空间页仍可见并带「仅自己」标记，切到其他成员即消失）；否则 `plan.hiddenInSpace` 隐藏；否则默认公开。动态流**只展示 `status === 'done'`**；内容/合集仅 `publishedToSpace === true` 可见；聚合 `cheerCountByCheckIn` 与 `cheeredByViewer: Set<ID>`。

### 2.2 三条铁律的代码级落地

| 铁律 | 落地 | 复核 |
| --- | --- | --- |
| 1 · 两套状态独立 | `setContentCompletion` 只 `set({contents: ...completion})`；`setCheckInStatus` 只 `set({checkIns: ...status})`；关联字段只存 `ID[]`；跳转统一 `navigateToContent(id)`；类型层 `AppActions` 无 `syncXxx`/`markBothDone` | `sync[A-Z]` / `markBothDone` 命中数 = 0（仅注释提及禁令）；无跨数组写入 |
| 2 · 应完成日同源 | `CalendarPage` 用 `deriveAllDueDates` 算一次 `dueDates`，下传 `StreakCards`（`computeStreak`）、`MonthHeatmap`（`getHeatmapStatus`）、`DayDetail`、`HistoryView`；`DayDetail`/`HistoryView`/`PlanManager` 反查排期均调 `deriveDueDates` | 页面 `getDay()` 命中数 = 0（仅注释）；`deriveDueDates` 全项目 21 处引用均为复用 |
| 3 · 可见性唯一入口 | `computeSpaceView` 只在 `src/domain/visibility.ts` 定义，经 `useSpaceView` 供给 `SpacePage` → `SpaceHeader`/`Feed`/`SharedContent`；`SpaceHeader` 切换仅调 `setCurrentViewerId`（silent，不落盘、不缓存） | 组件/页面 `filter(c => c.visibility === 'public')` 命中数 = 0；无 `globalIncognito` / `PermissionLevel` / `AccessScope` / `FieldRule` |

### 2.3 主理人已批准的两处口径

1. `self_only` 短路 —— `visibility.ts` 第 35–41 行原样实现，六行真值表全覆盖。
2. 补卡窗口 `0 ≤ diff ≤ 7` —— `canBackfill`；`upsertCheckIn` / `setCheckInStatus` 额外阻断「未来排期日写 `done`」，但 `leave`（提前请假）始终允许；`computeSpaceView` 只展示 `done`。

### 2.4 MUI + Tailwind 四条共存配置

`preflight: false`；`main.tsx` 用 `StyledEngineProvider injectFirst` 包 `ThemeProvider`；MUI `breakpoints.values.lg = 1024` 与 Tailwind `screens.lg = '1024px'` 对齐；`useResponsive()` 是唯一 `useMediaQuery('(min-width:1024px)')`。交互组件走 MUI，Tailwind 只管布局/间距/响应式；未在同一元素上用 `sx` 与 Tailwind 类写同一 CSS 属性。

### 2.5 IndexedDB / 图片 / PWA

- 库 `huoye_leaf_db` v1；`state` 存单个 `AppState` JSON 快照（不含 Blob）；`assets` 存 `{id, blob, mime, name, createdAt}`。`bootstrap()` 首次 `buildDemoData() → writeState() + buildDemoAssets() 逐个 writeAsset`，已有数据直接恢复；`hydrated` 门禁通过后才渲染三模块。action 先 `set()`，订阅在微任务内合并 `persistState(snapshot)`。
- 本地文件 → `putAsset` → `useAssetUrl()` 惰性 `createObjectURL`、卸载 `revoke`；外链封面（seed 里故意用 `example.invalid`）一律 `onError → PlaceholderImage`；剪藏图集走本地上传。
- 预览三路径：`recognizeSource` → `PreviewRouter` → `BilibiliPlayer`（官方 `player.bilibili.com/player.html?bvid=...&autoplay=0`，超时/手动降级/`CoverFallback`）/ `ClipReader` / `LocalPreview`。**全项目 `fetch()` 实调用数 = 0**；`sourceUrl` 只出现在 `CoverFallback` / `ClipReader` 的「去原站」按钮且需用户主动点击。
- 最小 PWA：`generateSW`、`registerType:'autoUpdate'`、`injectRegister:null` + `main.tsx` 手动 `registerSW()`；manifest `standalone` + 192/512 图标；`globPatterns` 仅本地构建产物、`navigateFallback:'/index.html'`、**`runtimeCaching: []`**。若本地构建成功，产物应含 `dist/sw.js` 与 `dist/workbox-*.js`（本工作区当前无 `dist/`，构建未在此执行）。

### 2.6 预置示例数据（Q6）

10 条内容覆盖 B 站可播（2）、剪藏卡片（3）、本地图片（2）、本地笔记（2）、外链兜底（1）；3 名成员；3 个计划（`daily` / `weekly_n [1,3,5]` / `specific_weekdays [1..5]`，其中第 3 个 `hiddenInSpace: true`）；约 30 天打卡历史（`subDays(today, 29)`）由 `deriveDueDates` 同源生成，**刻意包含请假、漏打、补卡、`self_only`、`hiddenInSpace` 计划、未来日期提前请假、无计划临时记录**，保证首次打开即可演示身份切换差异。占位图为内联 SVG 字符串 → `Blob`，不出浏览器、永不失败。

### 2.7 三个 tab / 无路由

`TABS = 活页 / 日历页 / 家庭空间`（第三个不叫「共享内容」）。无 react-router、无 react-hook-form；3 tab 与二级页全部由 Zustand UI 状态（`activeTab` / `selectedContentId` / `selectedDate` / `detailView`）驱动。`setActiveTab` 复位 `detailView`，刷新回默认 tab 但数据完整保留。
